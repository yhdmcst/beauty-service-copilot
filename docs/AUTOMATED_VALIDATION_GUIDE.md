# 自动预检查与本人确认

更新：2026-10-13。可以减少重复劳动，不能把模型结果写成真人确认。本轮真实人工标注与12条本人回复复核均保持原状态。

## 哪些工作可以交给工具

| 工作 | 可以替代的部分 | 仍需本人确认的部分 |
| --- | --- | --- |
| 回复逐条预检查 | 金额/状态/承诺规则，证据忠实性、共情和下一步的模型预审，按分歧排序 | 原话是否真的被理解、处理方案是否符合业务 |
| 标注一致性检查 | 查缺字段、非法标签、重复任务、规则与模型分歧 | 决定金标准标签；模型预测不等于第二名标注者 |
| 回复质量评估 | 固定用例回归、错误注入、参考模型评分 | 独立语义正确率需要实际独立标签，已经见过的回归不是盲测 |
| 效率比较 | 系统请求用量/耗时、模拟工作负载 | 本人实际任务完成时长，不能用模型耗时代替 |
| 风险处置 | 自动登记、跟踪任务与定位来源 | 当前症状、退款结果、业务处理完成仍需核实 |

赛题鼓励可量化评估，没有规定必须多人标注或做完整人工人效试验。可以如实用工程协议、原人工标注事后回归和自动预审参赛；不必把自动预审伪装成人工验证来补数字。

## 本轮已做的工具

`evaluation/review_saved_replies.py`读取已有首遍回复，不重新生成候选。先执行当前业务规则，再可选调用本地模型按五项检查：证据来源、具体共情、核查下一步、重复询问/工作转嫁、风险与承诺。输出引用必须能在输入原文找到；找不到时改为不确定。

该工具不往人工数据库写入，也不修改冻结模板、已有回复或标签。原记录前后哈希另存。每条开启模型预审会多一次评测调用，作为离线成本单列，不能叫零Token。生成模型和评审模型相同时，明确标记同模型自评偏差。

本轮12条自动预审已完成：规则无剩余检出、模型五项无检出、零评审异常，仍保留12条待本人确认。自适应交替测量总Token为11788、完整格式15326，减少23.08%，不能并入原接待用量或称人工通过率。2026-10-14依据原始文件更正汇总，先前27.77%数字不采用。此前首轮误报和校准结果原样保留。当前评审沿用同一Qwen3:8b，自评与提示修改均可能影响结果，需要本人最后确认。

自适应分流后，同一12条交替复核使用约11788 Token，完整格式约15326 Token，减少约23.08%，问题标记一致。规则问题直接进入人工优先队列，高/紧急仍使用完整评审，普通项使用紧凑输出。人工确认仍是12条待确认。

运行示例：

```powershell
.venv\Scripts\python.exe -B -X utf8 evaluation/review_saved_replies.py `
  --input evaluation/results/communication_gpu_release_20261013_v3/reply_cases.json `
  --output evaluation/results/my_new_review --judge --adaptive
```

输出目录必须是新目录；已有证据不覆盖。不加 `--judge` 只做规则、整理和导出。

## 你只需怎么操作

1. 打开本轮生成的 `review.html`，先看靠前的高风险、问题和不确定回复。列表后面的回复仍应做一次最终确认，不能因模型通过就批量记成人工通过。
2. 每条只确认三件事：有没有编造事实；有没有漏掉当前诉求或实际风险；客户已经给过的资料有没有被再次索取。认可就记录通过，不认可就写哪句有问题和需要怎样改。
3. 需要标注工具时，在Label Studio导入 `label_studio_config.xml`，再导入 `label_studio_blind.json`，这份不显示模型预测。完成后导出结果，别导入原人工库覆盖30条金标签。
4. 若只是想省时间、无需声称盲测，可导入 `label_studio_assisted.json`；它只有模型 `predictions`，没有完成的 `annotations`。结果应记作看过预判后的本人确认。
5. `promptfooconfig.json`可让Promptfoo对同一已保存输出评分。候选使用echo路径，不再重新生成；评审提供方明确是本地Ollama，避免自动挑选云端提供方。

Promptfoo当前所查版本为0.124.1，要求Node至少22.22.0。本机Node20.20.1尚不满足，本轮未安装它。配置是已生成、未用其CLI实跑；本项目原生自动预审单独记录真实运行。
