# 技术架构

## 组件关系

| 层次 | 组件 | 职责 |
| --- | --- | --- |
| 交互层 | HTML / CSS / JavaScript、Socket.IO | 会话浏览、建议审核、风险看板与评估中心 |
| 应用层 | Flask API | 查询业务记录，提交分析，保存人工操作 |
| 编排层 | LangGraph、生成队列 | 按节点取证、识别风险、生成并保存结果 |
| 分析层 | 诉求规则、服务状态、资料视图、Qwen3:8b | 组织当前问题与回复计划，生成结构化草稿 |
| 校验层 | 知识范围、JSON Schema、Pydantic、业务检查 | 筛选可用资料，检查字段、状态与执行承诺 |
| 数据层 | JSON、SQLite | 虚构业务记录、场景知识、分析与任务历史 |

默认使用词法检索和进程内缓存，运行Demo无需额外部署向量数据库或缓存服务。

## 工作流

| 节点 | 主要处理 |
| --- | --- |
| Evidence | 按会话和分析时点关联聊天、订单与工单，加入已确认身份的历史 |
| Safety | 识别当前诉求及服务风险，先保存需要跟进的风险任务 |
| Draft | 构建事项状态、已有资料和回复计划，检索适用知识，调用证据路径、缓存或模型，校验草稿 |
| Verify | 关联证据和时点提示，补充必要的人工复核任务 |
| Audit | 保存分析、节点耗时、模型用量及任务关联 |

实现入口：`src/orchestration/workbench_workflow.py`、`src/agents/assist_agent.py`。

## 多轮状态与资料

诉求候选保留原话位置、状态和订单指代。服务状态按稳定事项编号延续，区分漏液、泵头和少件等问题，记录暂缓、撤销、重新提出和消费者自述解决。

已有资料保留消息ID、时间与所属会话。资料视图区分上传声明、图片消息记录与实际附件文件；后续更正保留来源。快照模式可读取同会话本地输入，历史回放排除分析时点之后的资料及后加输入。

回复计划组合已知信息、客服核查动作和必要追问。局部修复优先保留有效草稿，修正漏项、重复索取资料或未经核实的承诺。

## 知识与生成

知识检索核对意图、商品、品牌、渠道及有效期。仅本次通过支持检查的事实资料进入生成；处理流程以独立辅助字段提供。示例知识用于展示这两类用途。

模糊意图可由同次生成补判，意图变化后刷新检索范围并检查受影响草稿。基础情绪和场景标签分开，实际不适等风险由独立规则触发，模型不能降低规则给出的风险下限。

## 并发、缓存与异常

默认生成队列为1个worker、容量3。风险准备先于排队，队列拒绝或模型超时仍保留已登记事项。界面显示降级状态及待核建议。

精确缓存按提示版本、模型与运行配置隔离。重复请求命中缓存后仍检查当前风险。中间诉求发生变化时保留变化过程，重新生成。当前采用精确匹配，避免相似咨询复用不同订单事实。

## 存储与人工操作

SQLite保存分析、审核、身份确认及任务操作。风险任务可关联多次分析，负责人、等待对象、期限和重开原因分别留存。页面切换后旧请求的结果和任务弹窗受到视图版本检查。

人工审核在生成后的应用接口完成。LangGraph用于节点编排，图中断审批和图运行检查点不属于当前实现。评测脚本的逐条断点续跑是独立机制，见 [评估说明](EVALUATION.md)。
