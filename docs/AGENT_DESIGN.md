# Agent设计

## 目标与输入

辅助美妆电商客服理解当前问题、核对服务经过、审核回复并跟进未完成事项。输入为会话ID、选定买家消息、可选补充问题和分析模式。附件快照展示现有业务字段，历史回放以选定消息为截点。

`ContestDataStore`读取聊天、订单与工单。脱敏同名提供身份候选，人工确认并填写依据后才合并跨会话轨迹。

## 状态与节点

`AssistState`保存单次分析的会话、消息、时点、上下文、规则信号、分析ID、草稿、任务ID和执行记录。消费者之间不共享可变调用状态。

| 节点 | 输入与处理 | 输出 |
| --- | --- | --- |
| evidence | 会话、分析点、模式与已确认关联 | 合法业务上下文、证据与来源 |
| safety | 消费者原话及历史线索 | 诉求、情绪、风险与预先登记的任务 |
| draft | 上下文、事项状态、资料与适用知识 | 摘要、回复草稿、必要追问、下一步、原稿与校验调整 |
| verify | 草稿、证据、风险任务 | 来源提示及需要补充的人工复核任务 |
| audit | 分析结果、节点耗时与用量 | 本地分析记录、任务关联和完成通知 |

节点实现位于 `src/orchestration/workbench_workflow.py`。

## 分析与生成

`AssistAgent`协调意图、情绪、风险、沟通重点、已有资料和回复生成。明确诉求由规则定位，低置信意图与回复共用一次模型调用补判。

`service_state`按事项延续状态并保留变化依据。条件咨询不直接覆盖有效请求，局部问题解决仅更新对应事项，退款预测或退货入库不当作到账结果。多订单指代不清时保留待核关系。

`response_plan`将已知信息、客服动作和追问理由组织为提示。消费者已给材料时，先检查现有资料；不适反馈优先确认当前状况。校验在必要处局部修复，并保存修正原因。

`QwenWrapper`通过本地Ollama兼容接口调用文本模型 `qwen3:8b`。small与large配置可指向同一模型。JSON Schema和Pydantic约束字段，业务规则检查金额、状态、来源及执行承诺。

## 知识与证据

处理流程用于帮助客服核查，事实资料用于支持具体声明。检索分别检查用途、意图、商品及渠道等适用范围，生成只读取通过本次检查的资料。资料排序不能改变审核状态。

照片提供声明、肤质自述和消费者所称解决均保留来源及语义边界。消费者陈述与订单、工单字段并列展示，由客服核查差异。

## 人工决策与任务

客服可以编辑、采纳或拒绝草稿，填写审核人及备注。任务支持认领、等待对象、期限、处置备注、完成和带原因重开。重复风险关联到同一事项时保留历次分析，较高风险升级任务优先级。

工具读取业务记录并保存本地建议和操作，不调用真实退款、补发、改址或客户消息发送接口。人工审核在生成后的应用流程进行。

## 调用成本与异常

紧凑字段和360 Token输出上限控制单次生成。精确缓存按版本与模型配置隔离，命中缓存仍执行当前风险检查。明确且无争议的低风险查询可走证据路径。

模型不可用、超时、结构失败或队列拒绝时返回待人工核实的建议，记录降级原因。风险任务在生成前登记，避免生成等待阻断跟进。运行与回归方法见 [运行指南](QUICKSTART.md)、[评估说明](EVALUATION.md)。
