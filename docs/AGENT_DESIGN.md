# Agent设计

版本：`compact-v10-service-continuity-3`。

## 输入与状态

输入包括会话ID、选定买家消息、可选补充问题和分析模式。`ContestDataStore`读取聊天、订单和工单，加入人工确认身份的跨会话记录。

LangGraph的 `AssistState`保存本次会话、消息、时点、上下文、规则信号、分析ID、结果、任务ID和执行记录。可变状态按调用隔离。

## 节点

固定执行路径：

`evidence → safety → draft → verify → audit`

| 节点 | 输入与处理 | 输出 |
| --- | --- | --- |
| evidence | 按会话、消息时点和模式取数 | 上下文、当前问题、证据及来源 |
| safety | 识别诉求、基础情绪、场景和风险，重建买家报告的事项状态 | 规则信号、事项变化；保存并通知风险任务 |
| draft | 复用资料，规划客服核查和必要追问，检查知识支持，读取缓存或生成 | 摘要、回复、下一步、原稿及调整记录 |
| verify | 核对来源和时点，高风险结果补充人工复核任务 | 关联任务、服务轨迹和警示 |
| audit | 保存结果及各节点耗时 | 分析记录、Token用量、完成通知 |

实现位置：`src/orchestration/workbench_workflow.py`。

## 模型与工具

`AssistAgent`组合意图、情绪、风险、沟通重点、资料复用和回复生成。`QwenWrapper`调用本地Ollama；当前small和large配置均使用 `qwen3:8b`。

规则提供明确诉求和安全下限，模糊意图由同次生成补判。知识检索只向生成器传入通过当前支持检查的正文。业务规则检查金额、状态、未执行承诺及服务行为。

`service_state`记录买家表述中的事项变化，买家说“已解决”仍需与后台状态区分。`response_plan`列出已有资料、客服先查内容及最多一个必要追问，供客服起草时使用。

## 人工操作

生成后，客服在工作台修改、采纳或拒绝草稿，填写审核人和理由。任务认领、备注、状态更新单独保存到SQLite，并保留操作历史。

人工审核通过应用接口进行。本版没有使用LangGraph的 `interrupt` 或持久化checkpoint。任务完成只更新本地跟进状态，真实售后操作在业务系统中办理。

## 成本与异常

单次输出上限360 Token。精确缓存隔离提示版本和模型配置，不使用语义缓存，以免相似咨询复用错误订单事实。

默认生成队列1个worker、容量3。证据读取和风险登记在排队前完成；队列满、模型超时或结构失败时保留风险任务，并返回带降级状态的待核建议。

明确问候和严格满足条件的既往发货查询走证据路径。负面情绪、历史争议、风险及混合问题继续生成分析。

## 验证

测试覆盖时点、身份、事项变化、资料复用、风险、声明、缓存及人工操作。模型测量和人工复核范围见 [评估说明](EVALUATION.md)，当前限制见 [使用限制](KNOWN_LIMITATIONS.md)。
