# Agent设计

版本：`compact-v9-item-issues-2`。本文件说明实际工作流，可作为决赛Agent设计材料；不把后续规划写成已部署能力。

## 目标与输入

辅助美妆电商人工客服理解当前问题、核对服务记录、审核回复并跟进风险。输入包括会话ID、选定买家消息、可选补充问题和分析模式。默认附件快照；历史回放以选定消息为时点。

`ContestDataStore`读取聊天、订单和工单。昵称相似只提供身份候选，已由人工填写依据确认的关联才进入跨会话服务轨迹。历史回放排除未来消息和工单，缺失历史状态保留为未知。

## 执行流程

使用LangGraph `StateGraph`，入口到出口为固定有向路径：

`evidence → safety → draft → verify → audit`

| 节点 | 输入与处理 | 输出及副作用 |
| --- | --- | --- |
| evidence | 按会话、消息时点和模式取数，加入已确认的服务历史 | 上下文、当前问题、合法证据及来源 |
| safety | 规则识别当前诉求、基础/场景情绪和服务风险 | 保存并通知风险任务；在进入生成队列前执行 |
| draft | 复用已有资料；检查知识支持；精确缓存、限用证据路径或本地Qwen生成 | 摘要、情绪、风险、证据ID、待核项、回复和下一步；保留原稿及校验调整 |
| verify | 关联证据与时点提醒；高风险结果如无对应任务则补人工复核 | 任务ID、服务轨迹、来源与警示 |
| audit | 保存分析与各节点执行耗时 | SQLite分析记录、实际Token用量、完成通知 |

节点实现位于 `src/orchestration/workbench_workflow.py`。`AssistState`按单次调用保存会话、消息、时点、上下文、规则信号、分析ID、结果、任务ID和执行记录，不跨消费者共享可变状态。

## 模型和工具

- `AssistAgent`组合意图、情绪、风险、沟通重点、资料复用和回复生成，主实现为 `src/agents/assist_agent.py`。
- `QwenWrapper`调用本地Ollama兼容接口。已验证模型是文本版 `qwen3:8b`；small/large两个配置在当前环境指向同一模型，不代表部署了两种参数规模。
- 明确诉求由规则定位；低置信意图使用同次生成补判。基础情绪与业务场景标签分开，分类启发式分数不是校准概率。风险规则下限不由模型降低。
- 默认知识检索是词法演示。只有通过本次逐条支持检查的文档正文进入生成；排名不能替代审核授权。默认模拟知识不得作为品牌承诺。
- JSON Schema与Pydantic约束结构；业务规则再核对金额、状态、来源、未执行承诺和服务行为。检查不是完整事实证明。

工具读取业务记录、生成建议和保存本地任务，没有真实退款、补发、改址、诊断、鉴定或客户消息发送接口。

## 人工决策与持久化

客服在工作台修改、采纳或拒绝草稿，填写真实审核人。任务认领、备注和状态更新单独保存。SQLite保存分析、审核及任务历史；完成任务只改变本地跟进状态。

此版本没有使用LangGraph `interrupt`或持久化checkpoint。人工审核发生在生成结束后的应用接口，不能描述成已实现可恢复的图中断审批。

## 成本与异常处理

紧凑字段和360 Token单次输出上限限制生成。精确缓存按提示版本、提供方、模型配置等隔离，缓存命中仍执行本次风险检查。当前不使用语义缓存，避免相似咨询混用订单事实。

只有明确问候、无争议单订单既往发货查询等严格满足条件的请求走证据路径。负面情绪、历史争议、风险和混合问题继续完整分析。

默认生成队列1个worker、容量3。证据和风险先准备，队列拒绝时保留已建风险任务并记录降级；模型超时、不可用或结构失败时给出待人工核实的保守建议，不伪装成模型成功。

## 验证与扩展

348项软件测试覆盖身份/时点、风险、声明、资料复用、缓存和人工流程；当前模型及标签回归见 [项目报告](FINAL_PROJECT_REPORT.md)。所有自动预审结果保留真实来源，不能替代人工金标准。

后续先补未见表达和高风险样本，再验证图片输入、审核品牌资料及业务接口。生产鉴权、访问控制、租户隔离与并发部署需要单独实现和验收，不把本地演示直接暴露公网。
