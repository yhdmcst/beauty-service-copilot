# 美妆客服共情副驾：作品报告

## 场景与问题

美妆电商客服需要同时阅读聊天、核对订单并追踪售后工单。消费者已经说过的退款经过、提供过的照片和肤质顾虑，往往散落在不同记录里。接待人员既要快速回应，又要判断哪些问题仍未解决、哪些承诺尚无依据。

作品将服务理解、回复审核和风险跟进放进同一个工作台。设计重点是减少查找与重复说明，让客服知道消费者在等什么，以及自己下一步应该核查什么。

## 核心功能

| 接待环节 | 作品实现 |
| --- | --- |
| 还原服务经过 | 关联聊天、订单与五类售后工单，支持附件快照和历史回放 |
| 判断当前诉求 | 展示诉求原话、状态和处理顺序，区分条件、暂缓、撤销与重新提出 |
| 延续多轮服务 | 为事项保留编号与变化记录，区分漏液、泵头、少件等具体问题 |
| 形成针对性回应 | 提取等待结果、重复说明与肤质自述，沿用已给资料，生成回复计划 |
| 审核辅助建议 | 本地模型生成草稿，校验来源和业务声明，保存原稿、修正及人工决定 |
| 跟进服务风险 | 预警定位到会话，任务支持认领、期限、等待对象、完成和重开 |
| 记录效果 | 软件回归、固定场景评测与人工标注入口分别记录 |

## 创新设计

### 服务轨迹带有分析时点

关联多源数据后，还需要判断这些信息在当时是否已经存在。历史回放以选定买家消息为截点，排除后续消息和工单，无法还原的状态保留为未知。

退款案例S00381中，15:44:33的咨询早于16:26:33创建的工单。工作台可以显示两者的关联，也能在回放中排除晚42分钟产生的工单。这样，生成建议所依据的是当时可见的服务过程。

### 用事项状态延续对话

同一段话可能同时表达问题解决和问题延续。“漏液已经解决了，但泵头还是坏的”分别更新两个事项；“找不到再退款”保留为条件方案，“先别退款”则暂缓原诉求。状态变化保留来源，订单指代不明确时提示核实。

这种设计使客服可以沿着未完成的事项继续服务，减少每轮重新判断，也避免把局部解决当成整段售后完成。

### 共情对应具体服务动作

情绪标签只提供线索。生成建议还需考虑消费者在等待什么、是否已经反复提供材料，以及客服能直接查哪些记录。

作品把这些信息组织为沟通重点与回复计划：先回应具体困扰，再列出核查动作，最后只补必要的问题。例如消费者说照片已发，客服先核是否收到、可用及对应商品，再决定是否补问。肤质自述用于理解顾虑，保留原话来源。

### 风险在生成前进入跟进流程

工作流先登记风险，再进入模型生成队列。即使生成超时，需要处理的风险仍有本地任务记录。后续分析可关联同一任务，风险升级、期限调整和重开都有操作历史。

### 按用途使用知识和模型

场景知识分为处理流程与事实资料，检索时核对意图和适用范围。处理流程帮助客服组织下一步，订单或退款结果由对应业务记录支持。

明确低风险请求可走证据路径，精确重复请求复用缓存；复杂诉求和风险案例继续生成。成本控制与服务依据共同参与路由，避免为追求少调用而省略必要分析。

## 技术实现

Flask提供页面与接口，Socket.IO通知结果，LangGraph执行五节点工作流：`evidence → safety → draft → verify → audit`。本地Qwen3:8b生成结构化建议，SQLite保存分析、审核与任务历史。

诉求状态、资料范围和回复计划由规则组织，模糊意图复用同一次生成补判。JSON Schema、Pydantic与业务检查共同约束输出。人工编辑、采纳与拒绝通过工作台另行保存。

详见 [技术架构](ARCHITECTURE.md) 与 [Agent设计](AGENT_DESIGN.md)。

## 演示场景

- **退款受阻（S00381）**：核对退货、订单和工单，切换历史回放，生成建议并保存审核与跟进记录。
- **批次疑虑与举报表达（S00076）**：展示风险依据、任务认领及看板中的处理中状态。
- **商品少件（S00006）**：识别少件诉求，核对购买与实收信息，明确装箱、出库和分包核查动作。
- **局部解决后的继续跟进**：补充漏液与泵头问题，再说明漏液已解决，展示剩余事项及已有材料的沿用。

## 验证与作品价值

当前软件回归441项通过、3项可选依赖检查跳过。20条固定工程协议的意图与处理焦点均匹配。Qwen3:8b完整20条回归成功生成19条，1条超时降级；全请求中位约10.13秒。逐条证据、用量与单条复测见 [评估说明](EVALUATION.md)。

对消费者，作品针对已经表达的等待与顾虑组织回应。对客服，作品集中展示依据，把起草回复转为审核草稿与处理待核项。对服务管理，风险可以追溯到会话和负责人，未完成事项持续可见。

这些价值由可操作的演示流程与工程评测支撑。当前测量用于说明原型行为，尚未测量真实接待效率与满意度。

## 演示范围与扩展

作品使用赛题虚构数据和场景知识示例，完整展示人工客服辅助思路，不依赖真实品牌系统。应用保存草稿和跟进记录，真实退款、补发、改址及客户消息发送由业务人员在原平台处理。

多模态附件分析、更多自然表达和平台接口可作为后续扩展方向。参赛阶段以现有服务轨迹、多轮事项、资料复用和风险跟进交互体现方案价值。
