# 服务记忆开源研究与赛题对应

日期：2026-10-14。当前版本 `compact-v8-service-memory-5`。优化依据为 [赛题原文](CONTEST_BRIEF.md)，后续工作约束在 [项目持久记忆](PROJECT_MEMORY.md)。

## 本轮查阅

| 项目 | 已读源码与许可证 | 对本项目有用的机制 | 采用范围 |
| --- | --- | --- | --- |
| [LangMem](https://github.com/langchain-ai/langmem) | `src/langmem/knowledge/extraction.py`、LICENSE | schema约束的对话摘要/记忆，插入与更新可配置，namespace可分范围 | 借鉴结构化字段和范围隔离；未安装LangMem或使用其模型抽取流程 |
| [Mem0](https://github.com/mem0ai/mem0) | `mem0/memory/main.py`、LICENSE | user/agent/run身份范围及metadata不能任意覆盖身份；更新不应静默跨用户 | 借鉴资料来源、身份与历史隔离；未接入Mem0数据库、云端或自动改写记忆 |
| [Chatwoot](https://github.com/chatwoot/chatwoot) | `app/models/custom_attribute_definition.rb`、LICENSE | 联系人属性与会话属性分开，字段类型、账号和key范围明确 | 借鉴“已有资料”实操视图；未部署Chatwoot，不使用enterprise目录内容 |

LangMem采用MIT，Mem0采用Apache-2.0。Chatwoot本轮读取的非enterprise代码受MIT Expat条款约束，enterprise目录另有许可；第三方组件许可分别保留。这里只参考抽象机制，没有复制上游代码，也没有声称实现这些库全部功能。引入完整记忆框架会增加模型抽取、存储和身份管理开销，本机已有聊天/业务数据库可先完成当前需求。

## 已落地：来源可追踪的已有资料

工作台“沟通重点”下增加“已有资料”，展示：

- 已关联订单和现有运单/商品字段，客服先沿用，再核当前状态。
- 买家明确自述的肤质，保留原消息，不据此判产品适配。
- 买家称已经提供照片/截图，标为“自述、先核是否收到及可用”；不能推定图片文件存在。
- 图片消息记录与实际附件文件区分。提供材料没有文件时，明确标为附件文件未提供。
- 当前说法与此前材料自述冲突时保留分歧，不删除历史或默认认为资料完整。

当前或经确认关联的会话才提供资料，未来消息、客服话和他人材料不转成买家资料。已有字段只作核查起点，不代表诊断、退款到账、商品真假或附件内容识别。该机制不增加模型调用；本轮未把新增资料列表再塞入生成提示。

## 对应赛题与验收

| 赛题方向 | 本轮落实 | 测量边界 |
| --- | --- | --- |
| 信息孤岛与重复询问 | 订单字段、买家自述和图片消息统一显示来源 | 只展示当前已关联合法记录，不跨未确认身份自动合并 |
| 个性化与共情 | 沿用肤质/已给信息，减少反复说明负担 | 自述不等于专业商品推荐，不虚构品牌资料 |
| 风险与跟踪 | 实际不适安全优先，资料不能降低风险规则 | 工单闭环和原风险标签未改 |
| 性能/成本 | 本轮0新增模型调用；12例总Token8357，与前一版相同 | 中位2.83秒、最大4.87秒，顺序小样本，不能归因稳定提速 |
| 准确性/实用性 | 320项软件测试，12例最终声明/服务规则0检出，桌面/手机与两场景隔离彩排 | 自动检查不代填本人回复确认；原30条及全部旧输出保持 |

本轮新增资料测试覆盖否定/询问、第三方归属、未来消息、未确认跨会话、图片文件缺失、当前输入修改、历史说法冲突及来源/数量边界。软件通过不是消费者实际准确率。

## 项目记忆的使用

工作区根目录的 `AGENTS.md`要求在研究、修改和打包前读取赛题原文和项目记忆。它保存到本工作区，便于后续接着处理；不声称跨所有应用或新聊天的全局记忆自动生效。

每次优化先记赛题条款、实际客服问题、模型/Token/依赖成本、验证方式和采用结论。已有稳定版、失败实验、原人工证据分别保留。PPT不含团队分工；视频必须实际录制；多模态和更多模型不升级成必交条件。
